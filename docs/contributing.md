# Contribution Guide

## Purpose

This repository is a planning backbone for a disciplined trading system. Contributors should improve architecture clarity, product assumptions, and execution safety.

## Expectations

- maintain readable documentation
- document risk assumptions before implementation changes
- preserve the traceability of decisions
- prefer small, reviewable improvements

## Review checklist

Before a change is accepted, confirm:

- it matches a documented requirement or design objective
- the affected subsystem boundaries remain clear
- new dependencies are explicitly justified
- human review and operational safeguards are preserved
